Where everything lives

A check of every tab, segment, inner screen and toolbar, and what should move. Most of the app is already in the right place; this changes four things people will notice and tidies the rest underneath. Built from a full inventory of the code on 2026-11-23 (dev, after 490a008).

Verdict

  • Keep Five tabs: Today, Lists, Plans, House, Messages. The grouping idea is right; a sixth tab would push Messages off the bar's comfortable reach.
  • Keep Plans = Calendar, Meals, Movies (all "what are we doing"). Today, Messages, Settings behind the avatar, the dock, Add anything, Shopping's bottom composer.
  • Move Notes goes to House. Notes is the house's reference board (Wi-Fi password, the landlord's number, the bin day), not a list you tick off. In House it sits with the other things about the home, Lists becomes just the two real lists, and House stops being two Plus-only segments.
  • Move Avatar and bell share the left; each screen's own actions own the right, add at the far right. Today the bell takes the far-right corner on every tab, so "write new" can never be at the edge.
  • Fix Opening an event or a problem from another tab pushes only its detail, not a second whole Calendar or Problems screen underneath it.
  • Fix Names: Movies' "lists" become Watchlists; the bell's "House" half becomes Activity; one name per place everywhere.

Every tab now has at least one free segment, and each word means one thing.

  • Order inside House: Notes first for a free house, Money first for a Plus house (the default segment is chosen the same way the code already moves a free house off Calendar). After that, the remembered segment wins as today.
  • Lists with two segments is fine: Tasks and Shopping are the two things a household ticks off daily. It also frees space for a third list type later (packing, a party checklist) without inventing a tab.
  • Tab glyphs: Lists uses checklist, the same symbol as its Tasks segment; give the tab list.bullet.rectangle so tab and segment don't read as the same thing. House stays house.fill.
  • The House switch bar's "At a glance" icon stays (the counters must still live somewhere when Today's stats section is Off — CLAUDE.md, "nothing is removed"), but moves into the module bar as an ordinary trailing item so it obeys the same rule as everything else.
  • Migration: the per-device remembered segment for Lists may say "notes"; it falls back to Tasks, and House picks up Notes. No server change, no old-version concern: segments are device storage.

The top bar rule

One rule for every tab root, and it answers "write new should be on the right":

👤⌕✎🔔

Now (Notes): the bell owns the corner, compose is squeezed between search and the bell.

👤🔔⌕✎

Proposed: who-you-are and what-happened on the left; this screen's tools on the right, its add or compose last, at the edge.

  • Left (every tab): avatar (Settings), then the bell. They belong together: both are about you and the house, not about the screen.
  • Right (per screen): at most two items. Search (minimised, system), any one tool (history, "who's doing what", at a glance), and the add/compose action last, at the edge. If a screen has more tools than that, they go into one "⋯" menu before the add.
  • Add glyph: square.and.pencil where you write (Notes, a new chat), plus where you add a thing (task, event, recipe, watchlist, problem, money). Money keeps its "+" menu (expense, bill, budget).
  • Colour: the add is the one accent item in the bar; everything else neutral (the rule already in use since the colour pass).

Opening a specific thing from elsewhere

The rule in CLAUDE.md is right — a whole module switches tab, a specific thing opens in place on the stack that asked. The implementation of "in place" is where it goes wrong:

  • An event opened from Today, Money, Problems, Meals or the dock pushes a whole Calendar opened at that event. Back then lands on a calendar month the person never chose. Fix: push an EventDetail screen (the same content as the detail sheet, as a page). Inside Calendar it stays a sheet.
  • A problem opened from Today or Money pushes a whole Problems screen with the detail on top. Fix: push IssueDetail only.
  • A recipe has two mechanisms (an in-screen destination inside Meals, a Route from Today). Fix: one Route.recipeDetail used by both.
  • Movie night, Who's doing what, At a glance, the archive: already pushed on the asking stack, keep.

This is invisible when it works and is the one change here that removes real confusion (two Back taps through screens nobody opened).

Consistency underneath

  • Inner switch: one component for every face switch inside a segment (Tasks, Meals, Calendar modes, Money, Problems, the bell) — the chip-style pill Money and Problems already use, not a system segmented control under the type-set segment switch (two stacked segmented controls is what the segment switch's type style was chosen to avoid).
  • Search: system minimised search (segmentSearchable) wherever the whole screen is searchable: Notes, Meals, Movies, Calendar, Tasks. In-content search only where it searches one face (Money's expenses, Problems' list).
  • Empty states: every module's empty state has the same add action as its bar, wording "Add the first …".
